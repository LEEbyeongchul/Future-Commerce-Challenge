## 1. shopmate: 기술 구조가 우리와 가장 비슷하다

**무엇인가:** 한국어 대화와 사진으로 상품을 찾고 장바구니·주문·반품까지 하는 쇼핑 에이전트. PostgreSQL + pgvector, Qwen3-VL 멀티모달 임베딩.

**가져올 점**

1. **사진 검색 흐름이 우리 룩 분해와 같다.** VLM이 사진에서 아이템 위치를 찾고, 고른 아이템을 잘라 멀티모달 임베딩으로 비슷한 상품을 찾는다.
2. **폴백(대체 경로)이 있다.** 메인 임베딩 서비스가 죽으면 SigLIP 2 이미지 검색과 텍스트 검색을 RRF(순위 결합)로 합쳐서 계속 동작한다.
3. **사용자가 직접 말한 조건만 하드 필터로 쓴다.** "5만 원 이하"는 SQL 조건으로 확실히 걸고, 나머지 의미("이거랑 비슷한데 더 밝은 색")는 의미 검색으로 처리한다.
4. **되돌릴 수 없는 작업은 승인 후 재검증한다.** 결제·취소·반품은 확인 대기 → 버튼 승인 → 재검증 순서. 승인은 만료되고, 같은 요청은 두 번 실행되지 않는다.
5. **결과 검증 단계가 있다.** 도구 결과를 원래 요청과 대조하고, 모델이 지어낸 상품 목록은 막는다.
6. **업로드 사진은 세션 DB에 두고 만료시킨다.**

**반영 계획**

| 항목 | 우리 쪽 반영 위치 | 시점 |
| --- | --- | --- |
| 아이템별 최대 금액·사이즈 = 하드 필터, 취향 = 소프트 점수 | 기술 가이드 5장, 예상 질문 | 발표 전 (설명만) |
| 결제 직전 재고·가격 재검증, 승인 만료, 중복 실행 방지 | 아키텍처 가드레일 설명 | 발표 전 (설명만) |
| "AI가 없는 상품을 지어내지 않게" 결과 검증 단계 | 아키텍처 Think 단계 | MVP |
| 임베딩 서비스 장애 시 폴백 검색 | 기술 가이드 | MVP |
| 업로드 사진 자동 만료 | 보안 설명, 마이페이지 공유 설정 | MVP |

## 2. adyen-acp-poc: 대리 결제가 실제로 어떻게 안전하게 되는가

**무엇인가:** LLM 쇼핑 에이전트가 사용자를 대신해 가맹점에서 사는 과정을, 결제사 Adyen의 에이전트 결제 규격(ACP) 문서대로 재현한 시연. 실제 Adyen 접근은 제한돼 있어서 문서 규격을 따르는 가짜 서버(목업)로 돌린다.

**가져올 점**

1. **사용자는 정확한 총액을 승인한다.** 그다음에야 결제 권한이 위임된다.
2. **위임 권한이 아주 좁다.** 1회용, 최대 금액 = 이번 결제 총액, 해당 가맹점과 해당 결제 건에만 사용 가능, 15분 후 만료.
3. **LLM은 카드 정보를 절대 보지 않는다.** 결제 도구는 결제 세션 ID만 받는다.
4. **가맹점이 결제 직전 재고·가격·위험을 다시 확인한다.**

**반영 계획**

| 항목 | 우리 쪽 반영 위치 | 시점 |
| --- | --- | --- |
| "대리 결제가 안전한가?" 답변에 이 구조를 인용 | 체크리스트 예상 질문 | **발표 전** |
| AIR Agent 권한 = 금액·쇼핑몰·시간이 제한된 1회용 권한으로 설명 | 기획서 인프라, 목업 결제 화면 | 발표 전 (문구) |
| 목업 결제 화면에 "이번 결제에만 · 15분 유효" 표시 | 목업 위임 권한 카드 | 선택 |

## 4. pickpick: 제출 형식과 추천 기록

**무엇인가:** 자연어 한 문장으로 실제 판매 상품을 비교하고 구매 판단을 돕는 쇼핑 에이전트. 배포까지 된 공모전 제출작.

**가져올 점**

1. **README가 제출 형식에 맞춰 정리돼 있다:** 서비스 소개, 문제 정의, 주요 기능, 기술 스택, 실행 방법, 배포 URL, 테스트 계정, LLM/Agent 구조, 데이터 흐름, 미구현 범위, 개선 방향, AI 도구 활용 여부.
2. **추천 당시 결과를 스냅샷으로 저장한다.** 나중에 가격이 바뀌어도 당시 추천을 그대로 보여준다.
3. **후속 요청에서 맥락을 유지한다.** "다른 거 추천해줘", "20만 원대로" 같은 요청에서 이전 조건을 기억하고, 이미 보여준 상품은 뺀다.

**반영 계획**

| 항목 | 우리 쪽 반영 위치 | 시점 |
| --- | --- | --- |
| README를 같은 형식으로 정리 (특히 **미구현 범위**, **AI 도구 활용**) | 깃허브 README | **발표 전** |
| 저장한 룩의 당시 추천 결과 보존 + 가격 변동 표시 ("저장 때보다 12% 내렸어요") | 홈 피드, 가격 감시 | MVP |
| "후보 더 보기"에서 이미 본 상품 제외 | 예산 맞춤 화면 | MVP |

## 5. K-BeautyGate: 발표와 README 연출

**무엇인가:** 외국인 관광객이 취향·피할 성분·예산·시간을 말하면 제품, 매장 동선, 직원용 한국어 카드를 만들어주는 K-뷰티 쇼핑 에이전트. 해커톤 출품작.

**가져올 점**

1. **첫 화면이 강하다.** 대표 이미지, 30초 쇼릴 영상, 웹 체험 링크를 README 맨 위에 둔다.
2. **"데모 범위"를 솔직하게 적는다.** 인물·브랜드·제품·후기는 가상 데이터이고, 정품 인증이 아니라고 명시한다.
3. **후보와 함께 제외 이유를 보여준다.** 왜 이 제품을 골랐는지뿐 아니라 왜 뺐는지도 알려준다.
4. **사용자에게 필요한 것 ↔ 서비스가 만드는 것** 표로 가치를 설명한다.

**반영 계획**

| 항목 | 우리 쪽 반영 위치 | 시점 |
| --- | --- | --- |
| README 맨 위에 목업 링크와 대표 화면 캡처 | 깃허브 README | **발표 전** |
| "데모 범위: 브랜드·상품·가격·리뷰는 모두 가상 예시" 고지 | README, 목업 첫 화면, 발표 | **발표 전** |
| 대체 후보에 "제외한 후보와 이유" 표시 (예: "통이 좁아서 뺐어요") | 목업 예산 맞춤 화면 | 선택 |
| 30초 시연 영상 | 제출물 | 시간 되면 |

## 6. OmniShopAgent: 실제로 돌아가는 시연을 만드는 가장 짧은 길

**무엇인가:** LangGraph로 만든 멀티모달 패션 쇼핑 에이전트. 텍스트 임베딩, CLIP 이미지 임베딩, Milvus 벡터 DB, Streamlit 화면.

**가져올 점**

1. **도구가 3개뿐이다:** 텍스트 검색, 이미지 유사도 검색, 사진 스타일 분석. 단순해서 금방 만들 수 있다.
2. **Kaggle의 공개 패션 상품 이미지 데이터셋(약 4만 4천 장)**으로 상품 DB를 만든다.
3. **멀티턴 대화:** "빨간 원피스" → "좀 더 포멀하게"처럼 이전 맥락을 이어간다.

**반영 계획**

| 항목 | 우리 쪽 반영 위치 | 시점 |
| --- | --- | --- |
| 공개 데이터셋 + CLIP으로 "사진 → 비슷한 옷" 실제 검색 시연 | 프로토타입 2단계 | 행사 이후 (데이터셋 라이선스 확인 필요) |
| "이 룩에서 니트만 더 캐주얼하게" 같은 대화형 수정 | 목업 확장 | 행사 이후 |

## 7. obadallyeo: "사지 말아야 할 이유"도 알려주기

## 반영 우선순위

**오늘 발표 전 (14:00–17:00 안에 가능한 것)**

1. README를 제출 형식으로 정리하고, 맨 위에 목업 링크와 "데모 범위(가상 데이터)" 고지 넣기
2. 예상 질문 답변에 대리 결제 근거 추가: Adyen ACP의 1회용·금액 제한·15분 만료 권한, 구글 AP2
3. 발표 실현성 파트에 "결제사와 구글이 에이전트 결제 표준을 만드는 중" 한 줄
4. 하드 필터(아이템별 최대 금액·사이즈)와 소프트 점수(취향)를 나눠 설명

**시간이 남으면**

5. 목업 결제 화면에 "이번 결제에만 · 15분 유효" 표시

7. 30초 시연 영상

**행사 이후 MVP**

8. 공개 패션 데이터셋 + CLIP으로 실제 이미지 검색 시연
9. 결과 검증 단계, 폴백 검색, 업로드 사진 자동 만료
10. 저장한 룩의 당시 결과 보존과 가격 변동 표시, 후속 요청 맥락 유지

## 주의

- 다른 팀 저장소는 **아이디어와 구조만 참고**하고 코드나 문구를 그대로 가져오지 않는다.
- ACP, UCP, AP2의 정확한 이름과 내용은 발표 전에 각 공식 문서로 확인한다.
- 공개 데이터셋은 사용 전에 라이선스를 확인한다.
