> 저장만 해두던 룩을 오늘 주문하는 옷으로.
> 사진 한 장으로 시작하는 패션 쇼핑 에이전트

| 행사 | Future Commerce Challenge 2026 (2026.11.22, Google Startup Campus Seoul) |

## 01. 문제: 발견은 1초, 구매는 끝나지 않는다

핀터레스트에서 좋아요를 누르고, 인스타 룩을 캡처한다. 그런데 그 사진들은 대부분 앨범에 쌓인 채로 끝난다. 사고 싶은 마음은 있는데, 사는 과정이 너무 길다.

> "이 옷 어디 거예요?" 인기 룩 게시물마다 달리는 댓글. 답은 대부분 오지 않는다.

| | 불편 | 설명 |
| --- | --- | --- |
| 1 | 찾기가 어렵다 | 댓글을 뒤지거나, 상의·하의·신발을 하나씩 따로 검색해야 한다 |
| 2 | 결제가 흩어져 있다 | 한 룩의 아이템이 서로 다른 쇼핑몰에 있어 결제를 몇 번씩 반복한다 |
| 3 | 사이즈가 불안하다 | 브랜드마다 사이즈가 달라 반품이 잦다. 패션 이커머스의 가장 큰 비용이기도 하다 |
| 4 | 예산이 안 맞는다 | 사진 속 룩은 비싸고, 비슷한 걸 더 싸게 찾는 데 또 시간이 든다 |

**해결:** 룩 사진을 올리면 에이전트가 아이템을 찾고, 내 사이즈와 예산에 맞춰 여러 쇼핑몰 결제를 한 번에 끝낸다.

## 02. 서비스 흐름: 사진 한 장에서 결제까지 여섯 단계

사용자가 하는 일은 사진을 올리고 마지막에 확인하는 것뿐이다.

| 단계 | 누가 | 이름 | 내용 |
| --- | --- | --- | --- |
| 1 | 사용자 | 영감 수집 | 핀터레스트 좋아요를 연동하거나 인스타 캡처를 올린다 |
| 2 | 에이전트 | 룩 분해 | 사진 속 상의·하의·신발·가방을 하나씩 인식한다 |
| 3 | 에이전트 | 상품 매칭 | 같은 상품, 혹은 가장 비슷한 상품을 여러 쇼핑몰에서 찾는다 |
| 4 | 에이전트 | 사이즈 맞춤 | 체형과 구매·반품 이력으로 브랜드별 사이즈를 고른다 |
| 5 | 에이전트 | 예산 맞춤 | 예산을 넘으면 내 취향을 학습한 대체 아이템으로 바꾼다 |
| 6 | 사용자 | 한 번에 결제 | 확인 한 번이면 여러 쇼핑몰 주문이 동시에 끝난다 |

### 핵심 기능 예시: "내 깔인데, 더 싸게"

예산 15만 원으로 룩을 맞추는 경우. 존재감이 큰 신발은 원본 그대로, 비슷한 대체품이 많은 니트와 데님은 취향이 겹치는 저렴한 아이템으로 바꾼다. (금액은 설명용 예시)

```
LOOK #024 · PINTEREST              budget 150,000
-------------------------------------------------
crop knit / M→L                       189,000 (원본)
  ↳ swap · 92% match                   42,000
wide denim / 27                       129,000 (원본)
  ↳ swap · 88% match                   39,900
loafer / 245                           59,000
shoulder bag                          -- owned
-------------------------------------------------
original look                         377,000
TOTAL · 3 shops                       140,900
```

## 03. 핵심 기능

| 기능 | 무엇을 하나 | 예시 |
| --- | --- | --- |
| 룩 분해 | 사진 한 장에서 아이템을 자동으로 나눠 인식 | 사진 1장 → 니트, 데님, 로퍼, 숄더백 |
| 사이즈 맞춤 | 체형과 구매·반품 이력으로 브랜드별 옵션 선택 | "이 브랜드 M은 작았어요. L로 골랐어요." |
| 취향 대체품 | 예산을 넘으면 학습된 스타일로 비슷하고 싼 아이템 추천 | 18만 원 니트 → 취향 92% 일치, 4만 원대 |
| 룩 예산 분배 | 룩 전체 예산 안에서 원본과 대체품을 조합 | 신발은 원본, 상의는 대체품 |
| 원클릭 결제 | 위임 한도 안에서 여러 쇼핑몰을 한 번에 결제 | 확인 1번 → 쇼핑몰 3곳 주문 |

추가 아이디어: 옷장 중복 체크 ("비슷한 검정 슬랙스가 이미 있어요. 상의만 살까요?")

## 04. 차별점: 렌즈는 검색, 우리는 에이전트

기존 서비스는 찾아주는 데서 멈춘다. 우리는 맞추고, 조정하고, 결제까지 한다.

| 기능 | 이미지 검색 렌즈 | 패션 플랫폼 스냅 | snap to buy |
| --- | :---: | :---: | :---: |
| 사진으로 상품 찾기 | ● | ◐ | ● |
| 룩 전체 한 번에 분해 | ◐ | ● | ● |
| 내 사이즈·체형 맞춤 | ○ | ◐ | ● |
| 예산 맞춤 대체품 | ○ | ○ | ● |
| 여러 쇼핑몰 한 번에 결제 | ○ | ○ | ● |

● 지원 · ◐ 일부 지원 · ○ 미지원 (팀에서 실제 서비스를 사용해 보고 보완 예정)

## 05. 아키텍처: 사진 한 장이 주문이 되기까지

모으고(Collect), 판단하고(Think), 실행한다(Act). 판단의 각 단계는 에이전트가 도구로 불러 쓰고, 실행은 사용자가 정한 권한 안에서만 일어난다.

```
┌─ COLLECT 데이터 수집 ─────────────────────────────────────┐
│ 영감 사진 · 상품 데이터 · 내 정보 · 옷장                   │
└──────────────────────────┬─────────────────────────────────┘
                           ▼
┌─ THINK AI 판단 (LLM 에이전트가 순서대로 호출) ─────────────┐
│ 룩 분해 → 상품 매칭 → 취향 점수 → 사이즈 → 예산 조합       │
└──────────────────────────┬─────────────────────────────────┘
                           ▼
┌─ ACT 실행 ────────────────────────────────────────────────┐
│ 한 번에 결제 · 골라서 결제 · 장바구니 담기 · 가격 내려가면 사기 │
│ AIR Agent · AIR Money · AIR Identity · Minds              │
└────────────────────────────────────────────────────────────┘
```

### Collect: 데이터 수집

| 데이터 | 수집 방법 |
| --- | --- |
| 영감 사진 | Pinterest 계정 연결로 좋아요한 핀을 가져온다. 인스타는 캡처나 공유하기로 업로드 |
| 상품 데이터 | 쇼핑몰 제휴 상품 피드(이미지, 가격, 재고, 사이즈 실측표). 초기에는 쇼핑 검색 API |
| 내 정보 | 가입 때 키·몸무게·평소 사이즈. 이후 구매 기록과 반품 사유가 쌓인다 |
| 옷장 | 앱에서 산 옷은 자동 등록, 가진 옷은 사진으로 추가. 중복 구매를 막는다 |

### Think: AI 판단

1. **룩 분해:** 이미지 인식으로 옷 영역을 찾아 아이템별로 잘라낸다.
2. **상품 매칭:** 이미지를 벡터로 바꿔 상품 DB에서 가장 닮은 상품을 찾는다. 거의 같으면 원본, 조금 다르면 대체 후보.
3. **취향 점수:** 내가 좋아요·구매한 옷의 벡터 평균이 "내 취향". 후보와의 거리를 0–100%로 바꾼 값이 92% 같은 숫자다.
4. **사이즈:** 상품 실측표를 나에게 잘 맞았던 옷의 실측과 비교한다. "작아서 반품" 이력이 있으면 한 치수 올린다.
5. **예산 조합:** 아이템별 후보 중 예산 안에서 취향 점수 합이 가장 큰 조합을 고른다. 룩의 포인트 아이템은 원본에 가중치.

LLM 에이전트가 다섯 단계를 순서대로 호출하고, 고른 이유를 사람 말로 설명한다.

### Act: 실행

| 결제 방식 | 동작 |
| --- | --- |
| 한 번에 결제 | 쇼핑몰 주문 API로 여러 곳을 동시에 주문 |
| 골라서 결제 | 체크한 아이템만 주문, 나머지는 찜하고 가격 감시 |
| 장바구니 담기 | 사이즈까지 맞춰 담기만 하고 결제는 사용자가 |
| 가격 내려가면 사기 | 가격을 주기적으로 확인, 목표가 이하에서 자동 주문 |

MVP는 Collect와 Think의 매칭까지, 그리고 구매 링크 제공으로 시작한다. 대리 결제는 쇼핑몰 제휴와 AIR 연동 이후 단계.

## 06. 인프라: AI가 대신 결제해도 안전한 이유

가장 어려운 부분인 대리 결제를 AIR와 Minds 인프라 위에서 설계한다.

| 스택 | 우리 서비스에서의 역할 |
| --- | --- |
| AIR Agent | "한 번에 최대 30만 원, 허용한 쇼핑몰만"처럼 권한 범위를 정하고, 판매자는 에이전트 신원을 검증한다 |
| AIR Money | 여러 쇼핑몰 결제를 하나로 묶어 정산한다 |
| AIR Identity | 사이즈·체형 등 필요한 정보만 골라서 공개한다 |
| AIR Loyalty | 쇼핑몰마다 흩어진 포인트를 예산 계산에 반영한다 |
| Minds | 상시 작동하는 개인 에이전트. 저장한 룩의 가격이 내려가면 먼저 알려준다 |

## 07. 수익 모델: 사용자는 무료, 수익은 판매자에서

| 수익원 | 방식 |
| --- | --- |
| 제휴 수수료 | 구매 1건당 일정 비율. 반품이 줄어드는 만큼 판매자도 이득이다 |
| 대체품 추천 광고 | "비슷하고 더 싼 아이템" 자리에 브랜드가 입찰한다 |
| 트렌드 리포트 | 많이 저장되고 팔리는 룩을 익명 통계로 브랜드에 제공한다 |

## 08. 로드맵: 검색에서 시작해 에이전트로

1. **P1 · MVP (찾기):** 사진 업로드 → 아이템 인식 → 구매 링크. 결제는 사용자가 직접.
2. **P2 · 맞춤 (사이즈와 예산):** 사이즈 자동 선택, 예산 내 대체품. 구매·반품 데이터로 취향 학습.
3. **P3 · 에이전트 (대리 결제):** 위임 한도 안에서 여러 쇼핑몰을 한 번에 결제. AIR 연동.

## 09. 예상 질문

| 질문 | 답변 방향 |
| --- | --- |
| 구글 렌즈랑 뭐가 달라요? | 렌즈는 찾아주는 데서 끝난다. 우리는 사이즈와 예산을 맞추고 결제까지 대신하는 에이전트다 |
| AI가 여러 쇼핑몰 결제를 어떻게 하나요? | 사용자가 위임 한도를 정하고, 에이전트는 그 안에서만 결제한다. 판매자는 AIR Agent로 에이전트 신원을 확인한다. 초기에는 구매 링크 제공부터 시작한다 |
| 사이즈는 어떻게 맞추나요? | 처음엔 키·몸무게·평소 사이즈를 입력하고, 구매·반품 이력이 쌓일수록 정확해진다. 반품 감소는 판매자에게도 이득이다 |
| 사진 속 상품이 품절이면요? | 그때가 대체품 추천이 빛나는 순간이다. 똑같은 건 없어도 내 취향에 가장 가까운 아이템을 보여준다 |
| 내 정보는 안전한가요? | 필요한 정보만 선택적으로 공개하고(AIR Identity), 한도를 넘는 결제는 항상 사용자 확인을 거친다 |
